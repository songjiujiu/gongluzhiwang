视频题材分析与原生小游戏 Demo 说明

版本 1.0    2026 年 10 月 8 日

公路之王是一款以公路冲突、闪避决策和夸张反转为核心的单人街机驾驶游戏。玩家在短关卡中处理加塞、刹车干扰与隧道变线，用车速、车道和有限次数的幻想技能争取主动，完成一场有起伏的公路小故事。

本版本面向策划、程序、美术与测试人员，提供可执行的三关规则、数值初稿、内容扩展方案和抖音原生小游戏说明。先验证事件是否看得懂、触控是否顺手、反转是否有反馈，再决定内容规模与商业化。

| 项目 | 本次定义 |
| --- | --- |
| 类型与视角 | 竖屏透视街机驾驶，Canvas 2D 绘制，固定三车道，单人短局 |
| 核心体验 | 发现挑衅 → 调整车速与位置 → 规避或气浪反转 → 获得反馈 → 继续推进 |
| Demo 内容 | 3 个 75 秒关卡，每关 4 次事件机会，至少成功 3 次；耐久、得分、结算、重试和选关 |
| 目标设备 | 抖音客户端内的手机小游戏；竖屏触控，支持安全区与不同屏幕比例 |
| 工程基线 | 原生 JavaScript 与 Canvas 2D，tt 平台适配，无引擎、网络或登录依赖 |
| 后续判断 | 观察玩家能否主动变速、读懂威胁，并愿意为更好成绩重玩 |

## 1 视频观察与玩法提炼

### 题材结构

来源清单包含 B站合集、方言二创、抖音动画与标注为原频道的 YouTube 视频。20 个不同链接不能直接视为 20 个独立剧情：V01 和 V02 是合集，V07 至 V14 是部分单集，跨平台视频也可能复用同一动画。内容规划按“冲突事件”归档，配音版本只作为表达参考。

本次画面分析覆盖 V07、V10、V13 三条公开视频的抽帧；其余 17 条保留为清单题材信息。三条均未完整听音或逐帧观看，以下观察只对应已查看画面。

V07 变道打灯的 25 秒画面显示驾驶视角中的红色前车，40 秒前车占比显著增大，形成车距压力；47 秒出口附近的字幕提到变道不打灯。20 秒驾驶员愤怒特写与 52 秒笑容形成情绪反差。这种路况、人物情绪、距离压力、短反馈的交替适合转化为事件预警节奏。

V10 心急闯红灯的 5、27、60 秒画面展示红色交通信号、路口和停止线前车辆；24、42 秒出现驾驶员表情与字幕。70 秒两车位置与朝向变化，不能据此确认完整碰撞或责任。可借鉴重复等待与情绪积累；当前 Demo 暂无红绿灯关卡。

V13 隧道超车的 12 秒画面中，两车占据不同车道；26 秒出现倾斜跑车和火花，36 秒出现警灯车辆，48 秒驾驶视角翻转，66 秒驾驶员露出惊讶表情。可借鉴受阻、夸张机动、新威胁与反差反馈的节奏。Demo 的连续变线 NPC 为原创交互，未复刻这些镜头。

清单标题另外覆盖安全车距、变道打灯、刹车干扰、高速插队、隧道超车与观察路况。游戏将这些题材转化为可辨识预警、可执行决策和短结果反馈，具体 NPC 状态、气浪技能和数值为原创设计。

### 转化原则

| 输入 | 设计提案 | 验证方式 |
| --- | --- | --- |
| 车距被打破 | 前车与插入车形成短时空间压力，玩家可减速或换道 | 首次游玩者能说清危险来自哪辆车 |
| 故意刹车 | 先出现橙色预警，再降低前车速度；多次干扰形成节奏变化 | 碰撞后玩家理解自己错过了哪个信号 |
| 隧道变线 | 用灯光与边墙提高空间感，事件车辆跨入玩家前方 | 隧道环境不遮挡预警与车道识别 |
| 夸张反转 | 原创气浪将挑衅车推出危险区，伴随粒子、音效和短促镜头反馈 | 成功命中后 0.5 秒内能感知结果 |
| 二创表达 | 原创短字幕与拟声反馈承担喜剧节奏 | 静音条件下仍能读懂事件 |

### 内容边界

角色对白、车辆外形、商标、配乐与视频镜头不直接搬入 Demo。保留“冲突升级后发生喜剧反转”的题材方向，用原创几何车辆、字幕和技能表达。游戏行为采用明显幻想表现，真实道路知识可作为可选说明；核心关卡不采用考试题库。

## 2 核心循环与操作

### 一局的节奏

玩家选择关卡后从中间车道出发。自动巡航后约 4 秒出现首次事件，之后约每 19 秒触发，共有四次机会；普通车流填充间隔。玩家需要至少化解三次事件，并存活到 75 秒。耐久耗尽立即失败，到时但事件成功数不足也会失败。

| 阶段 | 玩家决策 | 游戏反馈 |
| --- | --- | --- |
| 起步 0 至 4 秒 | 确认车道、尝试加速或减速 | 控制提示与清晰的速度变化 |
| 危险出现 | 观察事件车的颜色、标识和位置 | 事件标题、橙色危险提示 |
| 应对窗口 | 刹车、变道或消耗气浪冷却 | 车距变化、转向灯、技能状态 |
| 处理结果 | 保持安全或重新选择路径 | 事件处理数、得分或碰撞损失 |
| 局末 | 检查耐久与得分，决定重玩 | 结果、最高分和下一步按钮 |

### 操作映射

| 操作 | 手机触控 | 反馈与规则 |
| --- | --- | --- |
| 向左或向右换道 | 点击左右换道按钮；也可在道路区域左右滑动 | 车身平滑横移至邻道；一次滑动触发一次换道 |
| 加速 | 按住加速按钮 | 松手恢复巡航；手指移出按钮后释放 |
| 减速与刹车 | 按住刹车按钮 | 松手恢复巡航；同时按加速时刹车优先 |
| 转向灯 | 点击左灯或右灯 | 车灯闪烁、方向提示与打灯音效 |
| 幻想气浪 | 点击释放气浪 | 按钮显示可用或冷却 |
| 暂停与继续 | 点击右上角暂停；回前台后手动继续 | 暂停层提供继续、重开、选关及音效开关 |

### 操作取舍

车道切换使用离散输入，纵向速度连续变化，降低新玩家的方向控制负担。转向灯提供文明变道的反馈与得分机会，不将无灯变道直接设为立即失败。技能需要玩家判断前方目标和冷却，因此普通闪避始终保留价值。

## 3 玩家规则与数值初稿

### 数值口径

下表用于当前小游戏原型对齐。速度为显示值，空间使用独立于画面缩放的道路坐标；车道索引为 -1、0、1。规则按小时间步推进，不作为车辆真实性模拟。正式扩展前应通过手机实玩调整，再冻结外部配置。

| 项目 | 原型规则或建议 | 调节目的 |
| --- | --- | --- |
| 时长与通过 | 75 秒；存活且成功事件至少 3 次。每关约 4、23、42、61 秒触发 4 次事件 | 为一次事件失误保留补救机会 |
| 速度 | 初始 72 km/h；松开趋向 76；加速目标 118；刹车目标 25 | 街机巡航，刹车减速但不停车 |
| 速度变化率 | 加速 30、制动 62、回巡航 17 km/h 每秒 | 使制动比加速更迅速 |
| 换道 | 车道为 -1 / 0 / 1；横移速度 7.8÷3.35 车道/秒；间隔 0.42 秒 | 约 0.43 秒横移一车道 |
| 碰撞 | 起始耐久 100；每次扣 26 耐久、120 分；2.1 秒保护；分数最低 0 | 允许 3 次失误，第 4 次会耗尽耐久 |
| 打灯奖励 | 同向提前至少 1 秒且邻道清空，+30；奖励间隔 5 秒，灯 6 秒自动关闭 | 奖励前瞻操作，限制刷分 |
| 事件 | 2.4 秒预警；11 秒或驶到后方 12 单位时结束；无碰撞化解 +180 | 短且可复现的威胁窗口 |
| 气浪 | 10 秒冷却；覆盖车前 -4 至 36 单位的全车道车辆；推移 12 单位并加速离场 | 宽容的原型反转技能 |
| 反制得分 | 预警结束后命中当前事件车且事件未失败，+260；普通车不提供事件分 | 让气浪奖励和事件状态关联 |
| 结算 | 里程 ×0.12 取整；通关额外 +350+剩余耐久×3 | 生存、事件与驾驶质量共同影响成绩 |
| 星级 | 通关 1 星；耐久≥50 得 2 星；零碰撞且耐久≥90 得 3 星 | 提供清晰重玩目标 |

### 判定顺序

一帧内先处理玩家输入与冷却，再推进车辆和事件，随后执行碰撞、事件完成与关卡结束。暂停时停止关卡计时与危险推进。耐久归零的失败优先于到时成功，避免同帧出现双重结算。

### 碰撞与恢复

碰撞反馈应让玩家感知受损，且有短暂重复受击保护，防止同一辆车在连续帧扣光耐久。车辆退离或离开玩家后方后回收。Demo 使用可控的街机碰撞判定；真实轮胎、悬挂、车身破坏和翻车物理属于后续扩展。

### 气浪技能

气浪是为可玩 Demo 设计的原创幻想技能。点击技能后覆盖车前 -4 至 36 单位内的所有车道，包含普通车辆；效果推移 12 单位并使车辆加速离场。只有当前事件车已结束 2.4 秒预警、且事件没有因碰撞失败，才能获得反制奖励。空放也消耗 10 秒冷却。

## 4 车流与事件状态机

### 状态设计

普通车流负责空间变化，事件车负责可读的冲突。状态机如下表定义；当前 Demo 可以在单脚本内实现同等行为，量产阶段再拆分组件和数据。所有威胁都要在生效前留下玩家能够看到的预兆。

| 状态 | 进入条件 | 行为 | 退出条件 |
| --- | --- | --- | --- |
| 巡航 | 车辆生成 | 按目标车道与速度前进 | 进入事件脚本或驶离 |
| 预警 | 主事件触发 | 突出事件标记，显示短提示 | 预警时间结束 |
| 挑衅 | 预警完成 | 执行加塞、刹车或追随变线 | 玩家通过、气浪命中或碰撞 |
| 失去威胁 | 被玩家超越或反转 | 移出危险范围并计算事件结果 | 退出可见路段 |
| 回收 | 离开路段 | 清理对象和事件引用 | 重新生成 |

### 三类主事件

| 类型 | 规则 | 玩家解法 |
| --- | --- | --- |
| 加塞车 | 从邻道进入玩家前方，使安全距离收缩；不在车身重叠处瞬移 | 提前收速、打灯换道，或保留气浪到近距离 |
| 刹车车 | 在前方形成速度差，配合橙色警示；干扰前保留反应窗口 | 刹车维持间距，再寻找空道越过 |
| 变线车 | 隧道中切入相邻通行空间，制造横向威胁 | 延迟换道、改变车速或气浪反转 |

### 防止不可解局面

量产版事件导演应检查玩家附近空间：生成点不能与现有车重叠，危险进入期间至少保留一条可行路线或足够制动距离，连续事件之间应有恢复窗口。普通车流密度与主事件同时升级时，先保证公平性，再提高强度。

当前原型在事件生成前清除前方 12 至 43 单位内的普通车，留出事件空间；普通车同屏上限为 9，若目标车道前方 65 单位以远已有车则跳过生成。后续应进一步验证玩家附近的刹车距离和可行路线，减少只能靠技能化解的随机组合。

## 5 三关事件脚本

每关 75 秒，关卡主题按照清单题材确定。下表是互动事件脚本，不表示复刻任何视频的完整分镜。时间点和通过标准若与后续调参冲突，以工程交付说明为准。

### 第一关 留点距离

安全车距与加塞为主，第三次混入刹车，让玩家练习变速和换道。

| 阶段 | 事件 | 体验要求 |
| --- | --- | --- |
| 0 至 4 秒 | 自动巡航与控制提示 | 先确认触控换道和按住刹车 |
| 约 4 / 23 秒 | 两次加塞 | 邻道生成于前方 22 单位，2.4 秒后切入生成时玩家所在车道 |
| 约 42 秒 | 刹车干扰 | 前方 26 单位出现事件车，预警后减速 |
| 约 61 秒 | 加塞补充窗口 | 四次机会中成功三次即可满足事件条件 |
| 75 秒 | 结算 | 存活且成功事件≥3 时通关 |

### 第二关 别踩我的刹车

交替安排制动与横向干扰，要求玩家保留空间并判断技能时机。

| 阶段 | 事件 | 体验要求 |
| --- | --- | --- |
| 约 4 / 42 秒 | 刹车干扰 | 2.4 秒预警后事件车降至 22 km/h，事件时钟 6.8 秒后恢复 60 |
| 约 23 / 61 秒 | 加塞 | 预警后切入，速度取 max(25, 玩家速度-23) |
| 75 秒 | 结算 | 存活且成功事件≥3；鼓励低碰撞成绩 |

### 第三关 隧道博弈

用隧道拱架和连续变线考验横向预判，仍保留三条可见车道。

| 阶段 | 事件 | 体验要求 |
| --- | --- | --- |
| 约 4 / 23 / 42 / 61 秒 | 四次变线事件 | 预警后进入目标车道；事件时钟 5.2 秒后再移向相邻道 |
| 普通车流 | 生成间隔 3.8 秒 | 前两关为 4.5 秒；普通车目标速度 47 至 66 km/h |
| 75 秒 | 结算 | 存活且成功事件≥3 后完成三关挑战 |

## 6 界面与玩家引导

### 页面结构

| 页面 | 必要信息 | 主操作 |
| --- | --- | --- |
| 标题与选关 | 游戏名、三关主题、每关最高分、控制简表 | 开始指定关卡 |
| 驾驶画面 | 速度、耐久、得分、剩余时间、事件处理数、气浪冷却 | 驾驶、技能、暂停 |
| 事件提示 | 发生什么、危险车位置、短操作建议 | 继续驾驶；不遮挡道路 |
| 暂停 | 当前关卡与控制提醒 | 继续、重开、返回选关 |
| 成功结算 | 本局得分、最高分、事件完成情况 | 下一关或重玩 |
| 失败结算 | 失败原因与当前成绩 | 重试或返回选关 |

### HUD 布局

采用 540×960 逻辑画布等比缩放，在手机安全区内居中。顶部显示关卡、耐久、得分、速度、时间与事件进度；中部保留透视道路和事件标记。底部两排按钮：上排是左右换道、刹车、加速，下排是左灯、气浪、右灯。

### 引导文案

| 触发时机 | 文案建议 | 离场条件 |
| --- | --- | --- |
| 首次开始 | 点击或滑动换道，按住刹车与加速 | 选关页常驻；驾驶中使用短提示 |
| 首次出现加塞 | 前车突然切入，收油或换道 | 事件窗口结束 |
| 首次可用气浪 | 点击气浪，在橙车行动后反制 | 施放后切换为冷却提示 |
| 无效气浪 | 前方没有可反转的目标 | 短暂显示 |
| 碰撞 | 发生碰撞，保持距离再寻找机会 | 与受击保护一致 |
| 失败 | 耐久耗尽，重试本关 | 玩家点击重试或返回 |

### 可访问性与设置

颜色和文字同时标识事件，危险车不能只靠橙色识别。画布像素倍率最高为 2，适配安全区并预留上下边距。当前有音效开关与本地保存；后续增加振动开关、按钮尺寸调整和色弱标记。触控热区、刘海屏和小屏文字可读性仍需手机真机确认。

## 7 美术音效与演出

### 美术方向

当前使用 Canvas 2D 几何图形绘制车辆、透视道路、山体、树木与隧道拱架，靠色彩、缩放和遮挡形成纵深。玩家车为青色，事件车为橙色并有文字标记，普通车流降低饱和度。先确保小屏驾驶可读，再增加细节。

| 资产类别 | Demo 表现 | 后续扩展 |
| --- | --- | --- |
| 车辆 | 几何车体、车窗、轮胎、车灯与地面影子 | 原创车辆外观、受损状态、驾驶员剪影 |
| 道路 | 三车道、车道线、护栏与路边构件 | 弯道、匝道、收费站与城市边缘 |
| 隧道 | 透视拱架与较暗配色建立空间感 | 更丰富的墙面、入口与光照层次 |
| 事件标记 | 文字、颜色与简单几何提示 | 独立图标与预警动画 |
| 气浪 | 扩散圆环、车辆位移与音效反馈 | 分层冲击波、尾迹、短暂停顿 |
| 碰撞 | 耐久扣减与瞬时受击提示 | 火花、车身晃动与镜头反馈 |

### 声音分层

当前 Demo 已提供气浪、碰撞、成功提示、打灯四类程序合成音效。持续引擎声、路噪和背景音乐为后续设计：引擎随速度变化，事件预警应从环境声中可辨，命中与未命中可增加不同声音。正式版再替换为原创或已获授权素材。

| 声音 | 作用 | 量产要求 |
| --- | --- | --- |
| 引擎与路噪 | 传达加减速 | 连续循环无接缝，降低低频疲劳 |
| 预警与转向灯 | 让玩家捕捉状态变化 | 音色不同，支持单独音量控制 |
| 碰撞与气浪 | 确认失误或成功 | 短促有层次，不掩盖下一事件 |
| 结算与按钮 | 明确页面操作结果 | 一次触发，切换页面停止旧音 |

### 演出纪律

驾驶中不插入强制长镜头，不用长字幕遮挡车辆。喜剧反转来自事件节奏和车的夸张反应。对白、配音与人物剧情在玩法成立后增加，避免先投入大量无法复用的片段。

## 8 工程结构与数据扩展

### 原型结构

game.js 启动 RoadKingApp，通过 platform.js 连接 tt API。game-core.js 独立负责驾驶、车流、事件、得分和状态，可在 Node 测试中运行；game-app.js 处理绘制、触控、页面与声音分发。规则和平台边界已分离，扩展关卡时优先保持这种结构。

| 当前文件 | 职责 | 扩展方向 |
| --- | --- | --- |
| game.js | 创建平台适配与游戏应用 | 保持最小启动入口 |
| src/game-core.js | 速度、换道、碰撞、事件、技能、结算 | 逐步提取关卡和技能配置 |
| src/game-app.js | Canvas 绘制、按钮、滑动、页面与反馈 | 图形资源缓存和可调触控布局 |
| src/platform.js | 画布、系统信息、触控、生命周期、存储、声音 | 能力检测与真机兼容 |
| game.json | 声明 portrait 竖屏方向 | 保持产品方向一致 |
| project.config.json | 项目名称、原有 AppID、native 项目类型 | 保留项目身份与开发设置 |
| audio/*.wav | 四类原创短音效 | 可替换为授权音频资产 |

### 量产数据结构提案

| 数据 | 字段初稿 |
| --- | --- |
| LevelDefinition | id, title, duration, environment, trafficDensity, events[] |
| EventDefinition | id, type, triggerTime, startLane, targetLane, warningDuration, speedCurve, reward |
| VehicleDefinition | id, size, cruiseSpeed, colorRole, behaviorType |
| SkillDefinition | id, cooldown, forwardRange, laneTolerance, pushDistance, effectId |
| RunResult | levelId, score, elapsed, health, eventsCleared, collisions, bestScore |

配置建议使用 JavaScript 数据模块或 JSON，由脚本验证字段。事件 ID 必须唯一；触发时点不得超出关卡时长；事件结束时只记分一次。最高分按关卡存入 roadking.best.v1.0 至 roadking.best.v1.2，音效开关使用 roadking.muted.v1；存储异常不应阻止游戏运行。

### 性能方向

原型限制车流数量，回收超出路段的车辆，并把大时间差拆为不超过 0.05 秒的小步，减少慢帧穿透。表现层使用 Canvas 几何绘制，像素倍率上限 2。后续缓存重复道路元素与文字、减少每帧临时对象；帧率、发热与内存仍需目标手机测量。

## 11 迭代路线与工作量假设

### 决策顺序

第一轮先确认驾驶与事件有可玩性。邀请 5 至 8 位未看过工程的体验者，观察首次操作、第一次碰撞和第一次成功反转。让玩家描述发生了什么，再记录改动；不要只以“喜欢或不喜欢”的评价决定功能。

| 阶段 | 主要工作 | 结束条件 | 工作量假设 |
| --- | --- | --- | --- |
| 原型收敛 | 控制反馈、事件预警、公平性、三关调参 | 新玩家能完成首关并说明三类威胁 | 程序 3 至 5 人日，策划 2 至 3 人日 |
| 内容工具 | 配置拆分、对象池、事件编辑与校验 | 无需修改脚本即可添加一关 | 程序 5 至 8 人日，策划 3 至 4 人日 |
| 表现样板 | 原创车辆美术、环境图形、音效与技能演出 | 一关达到目标美术与音频标准 | 美术 6 至 10 人日，音频 2 至 3 人日 |
| 外部测试 | 输入设置、存档容错、目标设备性能 | 关键功能用例通过，严重问题清零 | 测试 4 至 6 人日，程序 3 至 5 人日 |

以上为后续工作估算，假设由一名熟悉 JavaScript 与抖音小游戏的程序、一名策划、兼职美术与测试完成，使用现有原型，不包含联网、商业化、完整剧情配音和平台审核。人日是投入量，可并行工作，不等同日历承诺。

### 体验指标

| 问题 | 建议观察 | 首轮判断标准 |
| --- | --- | --- |
| 是否读懂 | 首次事件后复述危险来源 | 多数体验者能指出目标车与危险行为 |
| 是否公平 | 碰撞前是否看到并理解预警 | 失误能归因于操作，减少无法理解的撞击 |
