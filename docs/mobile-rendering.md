# 手机画面优化

针对 1179×2556 真机截图反馈进行调整。当前保留用户设置，从强度 2 开始，夜景预览测试临时使用强度 4，不修改正式配置。

- 道路场景覆盖整个窗口，界面不再按 540×960 在长屏中垂直居中。顶部保留系统安全区及胶囊区域，底部提示栏贴近底部安全区；刘海和胶囊后仍绘制天空。
- 原生适配优先读取 `tt.getMenuButtonLayout()` 的有效 `bottom`，增加 6 CSS 像素间距；接口缺失、异常或返回无效数据时回退到系统安全区。参考[抖音官方安全区域适配说明](https://developer.open-douyin.com/docs/resource/zh-CN/mini-game/develop/guide/game-engine/godot/adaptation-checklist)。
- 合并时间、距离和强度信息，底部提示由 116 缩至 76 个逻辑像素；开局、升级、碰撞提示共用底栏，移除道路上方重复的引导条。底栏继续支持左右滑动与长按。
- WebGL 缓冲按手机实际画布像素设置，主画布 DPR 上限提高到 3，三维缓冲宽度最高 1080、总像素预算约 200 万，并遵守 GPU 最大纹理/渲染缓冲尺寸；393×852、DPR 3 时为 960×2082（上一版 786×1704，最初固定 540×960）。维持正确比例，不纵向拉长车辆。
- 透视近裁面由 0.12 米调整为 1 米、远裁面为 380 米，改善近处薄车灯与车身的深度分辨率。相机位置和画幅调整后，两侧换道时主车保持在画面内。
- 车漆清漆层、玻璃和普通材质分开着色，增加天空反射、玻璃上下渐变、随路灯变化的高光及车底接触阴影；道路颗粒降低对比度并在远处淡出，车道线使用屏幕导数平滑边缘。保留现有 Blender 模型，不新增模型包体。
- 在原生多重采样之后增加边缘检测抗锯齿（FXAA），Canvas 界面在其后合成，避免文字被滤镜模糊。分配纹理失败则保留原渲染；缺少导数扩展时使用按距离估算的车道线平滑。着色器世界坐标优先高精度，较低配置回退到中精度；循环路面位移归一化，避免长距离导致低精度溢出。

验证：74 项 Node 测试通过；390×844、320×568 常规浏览器回归，以及 393×852 / DPR 3 的夜景、晨雾、低精度片元着色器、无导数扩展、无抗锯齿纹理、2048 尺寸限制、胶囊占位、暂停、换道及长按检查。结果为 `research/blender-preview/mobile-ui.json`；`mobile-night-393.png` 为优化后模拟截图。前后对照由 `tools/verify_mobile_preview.cjs` 生成，其中历史版本对照需要仓库提交 `23acaee`。

浏览器模拟不能确认手机 GPU 性能或宿主真实返回值。本次尚未用手机重新运行，需重新编译并真机预览确认。

本次抗锯齿开启/关闭的像素比较确认滤镜生效，且平均色差小于 1 个 8 位通道值；该检查不能证明主观画质或真实手机帧率。FXAA 复制纹理约增加 6 MB 显存，分辨率提高会增加填充开销；尚未获取真机帧率数据。
